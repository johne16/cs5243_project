Overview

Object detectors are usually trained with full supervision: every image carries human-drawn boxes, and the network learns from that signal alone. Box annotation is the expensive part, and accuracy falls sharply when the labeled set is small.

Masked-image pretraining offers another source of signal. The backbone first learns from unlabeled images by hiding most of each image and reconstructing what was hidden; only then is the detector fine-tuned on labeled boxes. We measure how much detection accuracy that unlabeled stage buys, how the benefit changes as labels become scarce, and whether it behaves the same way for a transformer backbone and a convolutional one.

Prior work reports these gains under different schedules, augmentations, and detection heads, and pretrains on ImageNet-1K before fine-tuning on COCO. We place both backbone families in one shared protocol, pretrain on the same COCO images the detector later trains on so no outside data enters the comparison, and sweep the labeled-set size from 10% to 100%.

Research Question

Question

How much does masked-image pretraining on unlabeled COCO images improve object-detection accuracy over training from random initialization, and how does that gain change as the number of labeled training images shrinks, for both a transformer (ViTDet + MAE) and a CNN (Faster R-CNN + SparK)?

Hypothesis

AP drops for both the pretrained and the randomly initialized detector as the labeled fraction shrinks, but more slowly for the pretrained one, so the gap widens at smaller fractions. We expect the transformer to show the larger gap: it lacks the convolutional inductive bias and depends more on what pretraining supplies.

With ten labeled fractions (10% to 100%), two arms, and two backbone families, the design is 2 pretraining runs and 40 detection runs.

The pretraining methods

MAE

Hides 75% of image patches, encodes only the visible ones with a Vision Transformer, and reconstructs the missing pixels with a light decoder. Only the encoder is kept.

SparK

The convolutional counterpart. Sparse convolutions keep masked regions empty, and a hierarchical decoder lets a plain ConvNet train under the same masked objective.

ViTDet

Uses a plain, non-hierarchical ViT as a detection backbone, building a simple feature pyramid from its single-scale output.

Tiny backbones

With two A100 GPUs available, we use the tiny variant of each family rather than the sizes in the original papers. Neither ships as a released config (MAE and ViTDet provide ViT-B and larger; SparK provides ResNet-50 and larger), so both tiny configurations are written by hand.

Data

COCO 2017 has 118k training images, 5k validation images, and 80 classes with box annotations. Compute limits make the full dataset impractical, so the study runs on a reduced version:

  • Fixed class subset. The class list is narrowed to a fixed subset of the 80 categories, applied to both training and validation annotations.
  • Fixed image pool. A fixed random subset of train2017 images containing those classes is used for the whole study.
  • Same images in both stages. Pretraining sees the pool with annotations withheld; detection training uses the annotations.
  • Nested label fractions. The 10% split is contained in the 20% split, and so on; 100% is the full pool.
  • Evaluation. Always on val2017, restricted to the same class list.

Challenges and Limitations

  • Compute. Two pretraining runs plus forty detection runs force tiny backbones, short schedules, and a reduced image pool, so absolute AP sits well below published values.
  • Unequal arms. Training from scratch needs a much longer schedule to converge than fine-tuning. A schedule cut short overstates the benefit of pretraining, so we report AP over training to make undertraining visible.
  • Variance at small fractions. At 10% of labels, run-to-run variance from the sampled images can rival the effect being measured, so small-fraction settings are repeated with different seeds.
  • Integration. MAE and SparK come from separate codebases with their own conventions for normalization, learning-rate scaling, and layer-wise decay. Porting both into Detectron2 without silently changing one is a real risk.
